# ADR 0003：真实盘后流程采用单运行生命周期

- 状态：已接受
- 日期：2026-07-29

## 背景

真实盘后流程包含采集、双来源核对、候选审核、最终门禁和可恢复发布。可以让一个运行贯穿全部阶段，也可以把采集与发布拆成多个运行；后者会引入跨运行证据归属和失败恢复关系。

## 决策

1. 一个 `run_id` 贯穿真实盘后采集、候选审核和发布。
2. 采集、审核和发布是可独立失败、可恢复的动作，但不因此创建新的发布运行。
3. 有待审核候选项时，运行停留在 `AWAITING_REVIEW`；所有候选项处理完成后，发布动作重新执行全部门禁。
4. 发布前的暂停或进程中断按当前状态恢复。已发布内容保持不可覆盖；后续修订必须创建显式关联的新运行。

## 后果

- 报告、事实、候选项、警告、覆盖状态和运行事件共享直接的 `run_id` 审计边界。
- 暂存区必须支持跨进程保留与恢复，并继续由数据库控制正常可见性。
- 不允许先发布市场部分后原地补写政策或监管内容。
